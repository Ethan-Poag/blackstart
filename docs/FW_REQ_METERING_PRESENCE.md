# Firmware requirement: metering daughter board missing or silent = fault, engine shutdown

Status: **requirement only, not implemented.** Branch m7-split, written Nov 21, 2026 (HST); bus-side ruling added Nov 22, 2026 HST (Batch 30); bus-side breaker rule confirmed and power-dip rule FW-MTR-9 added Nov 22, 2026 HST (Batch 31); FW-MTR-9 running blind window capped at ≈ 2 s by Ethan and wired into the boot self-test, Nov 22, 2026 HST (Batch 32). No firmware file was changed. The separately held overvoltage engine-shutdown change stays held until Ethan says go. This note defines the "metering board missing" fault that it will rely on.

## Why
With the two-board split, the generator AC metering (2x ADE9000: GEN U71, BUS U72) lives on the HV metering daughter board (`genctl_meter`). It reaches the STM32 through J31 → harness (Molex Micro-Fit 2x8) → J32. A harness that backs out, a broken crimp or a dead daughter board would leave the controller blind to generator voltage, current and frequency. That includes the AC overvoltage protection. "Blind" must never look like "normal".

## Signals (main board)
| Signal | MCU / expander | Meaning |
|---|---|---|
| MTR_DET_N | U73 TCA9555 @0x20, P14 (pin 17). R636 10k pull-up to +3V3_SAFE. U73 INT is shared on I2C_INT_N | LOW = daughter plugged in (J32.15 is strapped to GND on the daughter). HIGH = harness or board missing |
| ADE SPI | SPI1 PA5/PA6/PA7; CS1 PA4 (GEN), CS2 PC4 (BUS); RST PC5; IRQ PB0 (GEN only) | Unchanged pins; now through J31/J32 |

## Requirements
- **FW-MTR-1 (presence):** read MTR_DET_N at boot and on every U73 interrupt. Also poll it at least every 100 ms as a backstop, because the INT line is shared. HIGH → `METERING_MISSING`.
- **FW-MTR-2 (liveness):** each ADE9000 must answer at boot and every ≤500 ms while metering is enabled.
  - The check is a read of a fixed-value register (for example VERSION) that returns the expected value, plus a running-status/sample counter that advances.
  - Three consecutive failures on either ADE → `METERING_SILENT` (per device: GEN, BUS).
  - All-0x00 or all-0xFF reads count as failures (MISO floats or stuck behind a missing isolator supply).
- **FW-MTR-3 (fault action):** `METERING_MISSING` or `METERING_SILENT` (GEN) is a **shutdown-class latched fault**.
  - Engine running: enter FAULT with the existing shutdown outputs (FUEL_EN = 0, GCB open), log to FRAM, buzzer, notify CM5/UI with the cause text "Metering board missing / not responding".
  - Engine stopped: the same fault blocks start (no auto-start, no manual start) until it clears and the operator resets.
  - **BUS-ADE-only silence (`METERING_SILENT` BUS with GEN healthy, Ethan's ruling, Nov 22, 2026 HST):** alarm (buzzer, log to FRAM, CM5/UI cause text "Bus metering not responding") and **block breaker close**: inhibit every bus-sync / GCB / MCB close permissive that needs bus voltage. **Never a shutdown**, in any configured mode. The engine keeps running and **a breaker that is already closed stays closed** (confirmed by Ethan, Nov 22, 2026 HST, Batch 31: bus-ADE silence never opens a closed GCB or MCB; it only inhibits new closes). The alarm latches like the others and clears per FW-MTR-5.
  - **Whole metering board missing or silent** (`METERING_MISSING`, or `METERING_SILENT` on GEN, or on both ADEs) is the latched shutdown described above, with start blocked (Ethan's ruling, Nov 22, 2026 HST).
- **FW-MTR-4 (no silent fallback):** never substitute last-known or zero values for live metering, and never treat a missing reading as "voltage OK".
- **FW-MTR-5 (recovery):** clearing needs MTR_DET_N LOW, both ADE liveness checks passing, a full ADE re-init (RST pulse on PC5, configuration rewrite and verify), and then an operator reset. No automatic restart. **Exception:** a supply event handled by FW-MTR-9 never latches, so its recovery is automatic (FW-MTR-9 "Pass"); only a FW-MTR-9 "Fail" goes through this clearing rule.
- **FW-MTR-6 (debounce):** MTR_DET_N must be HIGH for ≥3 consecutive samples (≥30 ms) before the fault is raised, so a single glitch does not trip. The liveness timeout (FW-MTR-2) bounds total detection time to ≤1.5 s.
- **FW-MTR-7 (UNCONFIGURED state):** in the factory-default UNCONFIGURED state (AC trips inhibited), still raise and show the fault and still block start. Engine protections are unaffected.
- **FW-MTR-9 (main 3.3 V dip / brownout is a supply fault, not "meter missing"; Batch 31, Ethan approved Nov 22, 2026 HST):** the meter board is powered from main **+3V3** through J31 (not +3V3_SAFE), and both ADE9000s run from the ISOW7841 isolated supplies (VISO = +3V3_AC, SEL = GND_AC → 3.3 V) whose input VCC1 is main +3V3. A +3V3 dip below the ISOW7841's VCC1 minimum for 3.3 V VISO (3.0 V) collapses +3V3_AC and stops or resets both ADEs while the STM32 keeps running. That must not latch `METERING_*`.
  - **Supply event** = any of: PSU_MAIN_OK (PC3_C, TPS2116 ST) low, **polled at least every 10 ms** (the primary detector; an EXTI edge on PC3_C may be added as well, but PC3_C digital/EXTI use is still UNVERIFIED, pinmap note 2); PSU_MAIN_OK low at any time in the last 2 s; or an ADE that answers VERSION correctly but reports it has reset (STATUS1.RSTDONE set, or its configuration read-back/checksum no longer matches). The last case catches dips that stay above the TPS2116 switchover (2.64–3.10 V) but below the ISOW7841's 3.0 V VCC1 minimum, so +3V3_AC sags and the ADEs reset without PSU_MAIN_OK ever going low.
  - **During the supply event:** suspend FW-MTR-2 liveness counting for both ADEs, put the ADE isolator drive pins in Hi-Z (ARCHITECTURE.md isolator rule), and log **one** `SUPPLY_3V3_DIP` entry to FRAM per event (start time, duration, min state seen), CM5/UI text "Main 3.3 V supply dip, metering paused". Do **not** log or latch `METERING_SILENT`. MTR_DET_N is still checked normally (its pull-up is on +3V3_SAFE and the strap is passive), so a really unplugged harness still raises `METERING_MISSING` per FW-MTR-1/6.
  - **Recovery recheck:** once PSU_MAIN_OK has been high for **100 ms** (settle; same 100 ms as the isolator restore rule), re-init both ADEs: RST pulse on PC5, wait for RSTDONE, full configuration write and verify (FW-MTR-5 sequence), then require **3 consecutive passing liveness checks at 100 ms intervals** on each ADE. The whole recheck window is **2.0 s** from PSU_MAIN_OK good. If PSU_MAIN_OK drops again inside the window, the event restarts.
  - **Pass:** both ADEs pass inside the window → metering resumes, no `METERING_*` fault, log `SUPPLY_3V3_DIP_RECOVERED`, no operator reset needed.
  - **Fail:** an ADE still fails at the end of the 2.0 s window with PSU_MAIN_OK continuously high → raise `METERING_SILENT` for that ADE and apply FW-MTR-3 exactly as before (GEN or both → latched shutdown / start block; BUS only → alarm plus breaker-close block, closed breaker stays closed).
  - **Engine running (Ethan's ruling, Nov 22, 2026 HST, Batch 32):** the blind window is capped at **≈ 2 s (2.0 s)** in total, counted from the first moment GEN metering is unavailable (dip included, repeated dips included). If both ADEs are not re-initialised and passing liveness by then, raise `METERING_SILENT` GEN (latched shutdown per FW-MTR-3); for a running engine this cap ends the recheck early, whichever of the cap or the 2.0 s recheck window comes first. This keeps a running set's protection (including over-voltage) blind for about as long as FW-MTR-6 already allows for a real loss (≤ 1.5 s) plus margin. The PSU_MAIN_OK fault path itself (ARCHITECTURE.md §12: shed loads, abort crank, back-off) runs in parallel and is unchanged.
  - **Engine stopped:** block starts **only while the event and its recheck are pending**, with UI text "Waiting for metering recheck after supply dip". When the recheck passes, starts are allowed again automatically (no latched fault, no operator reset). A start request that arrives meanwhile (auto-start or manual) is held, not discarded. It runs when the recheck has passed (≈ 2.1 s after power is good at most) **and** the ARCHITECTURE.md §12 PSU_MAIN_OK back-off (2–32 s, which also aborts cranks) has expired. So after a dip that tripped PSU_MAIN_OK, the held start waits for the longer of the two: ≈ 2.1 s for a dip that did not start a back-off (ADE-reset-only event), otherwise the current back-off step (2 s first, up to 32 s for repeats). The recheck never shortens the back-off, and the back-off never latches the metering fault. If the recheck fails, the FW-MTR-3 latched start block applies.
  - **Boot (Batch 32):** a boot with PSU_MAIN_OK low, or low at any time in the last 2 s (for example the controller starts on the battery buck before main +3V3 is up), is a supply event too. SELFTEST does not fail on the ADE checks in that case: it enters IDLE with starts blocked by this rule, runs the recovery recheck once PSU_MAIN_OK has been high for 100 ms, and latches only per "Fail" above (ARCHITECTURE.md §3 SELFTEST, §13.1 item 7). There is no boot-time limit on how long main +3V3 may take; starts stay blocked ("Waiting for main 3.3 V supply") until it comes and the recheck passes.
  - **Rate limit:** more than **5 supply events in 10 min** → raise `METERING_SILENT` GEN (latched, FW-MTR-3) with cause "Repeated 3.3 V dips", so a flapping supply cannot keep protection blind.
- **FW-MTR-8 (test):** bench test by unplugging the harness at each end while running on the bench supply. The fault must appear within 1.5 s, outputs must go to the shutdown state, and the CM5 must show the cause. Record the result in BRINGUP_CHECKLIST. **Power-dip test (FW-MTR-9):** with the meter board on the bench, pull main +3V3 down to ≈ 2.7 V for 50 ms and for 1 s (engine stopped, then simulated running). Expect a `SUPPLY_3V3_DIP` log, no `METERING_*` latch, starts blocked only until the recheck passes (≤ 2.1 s after power good). Then repeat with one ADE held in reset after the dip: `METERING_SILENT` must latch at the end of the 2.0 s window. Running case: a dip whose ADE recovery takes longer than 2 s in total must latch `METERING_SILENT` GEN (shutdown) at ≈ 2 s. Boot case: power up on the battery input with main +3V3 held off, then release it: no FAULT at SELFTEST, starts blocked until the recheck passes.
